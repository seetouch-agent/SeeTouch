# 本地记忆与经验积累

Android 1.5（versionCode 6）加入“任务完成时总结经验，下次相关任务加载”的闭环。记忆核心在 `seetouch/memory/`，Android 和 PC CLI 共用；存储与网关无关。

## 使用

在 App 设置中打开“记忆与经验”。可新增、编辑、停用、删除条目，或清空全部条目。偏好类别包括常用地址、联系人称呼、偏好平台和个人偏好；操作经验单独列出。名称和关联词用于检索，例如名称“家”、内容“同济大学嘉定校区”，可以匹配“用高德导航回家”；也可添加“回家、导航”等关联词。

“使用本地记忆”和“任务完成后自动积累经验”默认开启。关闭记忆后停止注入记忆上下文、建议保存及自动积累，已有条目保留；运行中的后续模型请求也会重新检查开关。单独关闭自动积累仍可使用已有条目。个人偏好建议显示在任务结果中，只有点击“确认保存这条偏好”才进入可检索的记忆库。

结果卡片显示本次匹配条目数、经验是否保存和待确认偏好。“没完成好”的评价会暂停本次匹配、或由本次生成的操作经验的自动复用；修改评价为正面可恢复，重复提交同一任务的评价不重复计数。记忆页也可手动重新启用。评价不会自动禁用地址等个人偏好。

## 总结、检索与反馈

1. 任务开始时，用名称、关联词和任务指令做中文词片/英文词匹配，最多选择 4 条相关记忆。无匹配时不填充无关条目。
2. 每一步把相关记忆作为参考数据加入现有模型上下文，仍执行截图、推理和安全检查。关闭、停用、删除或差评的条目不再注入后续请求；不会按旧坐标直接重放动作。
3. 在任务结束的同一模型响应中提炼经验，不另发总结请求。结构化内容必须有效，任务也必须被报告为完成，才保存操作经验。失败、用户终止、无总结或无有效总结时不保存；学习异常不覆盖任务结果。
4. 同一类别、名称和内容去重合并来源；条目保留来源任务和用户评价。正面评价可提高匹配条目的排序；负面评价阻止复用，形成可由用户纠正的经验反馈。

现有提示词及结果增加内容后会增加相应输入/输出 Token；不额外调用模型不等于不增加费用。模型可能省略总结或返回不合格内容，结果会显示“本次未生成可保存的经验”，不会生成假经验来填充。

结束响应示例（仅在启用记忆时请求这些可选字段）：

```json
{
  "action": "COMPLETE",
  "parameters": {
    "experience": {
      "name": "视频应用搜索",
      "keywords": ["视频应用", "搜索"],
      "content": "先确认已到首页，再进入搜索页，输入任务给定关键词，观察结果页后结束；已有搜索结果时可返回重来。"
    },
    "memory_suggestions": [
      {"category": "preference", "name": "搜索偏好", "content": "优先展示视频结果", "keywords": ["视频", "搜索"]}
    ]
  }
}
```

任务记录中保存匹配的记忆 ID、保存经验事件和学习状态；首个步骤的 notes 注明匹配条目。可用 `python scripts/replay.py runs/<task_id>` 查看这些记录。

## 存储与边界

Android 使用应用私有目录的 `agent_memory.json`；PC CLI 使用 `~/.seetouch/agent_memory.json`，本次禁用可传 `--no-memory`。Web 调试器暂未接入。最多保存 500 条，文件采用同进程加锁及原子替换写入，不自动清理用户条目；PC 不支持多个进程同时维护同一文件。文件损坏时任务继续运行而不加载记忆，原文件保留。用户明确清空可重建损坏的文件，重建后需重新打开记忆开关。

相关条目会发送给用户配置的推理服务；不会自动上传到网关或其他经验库。保存前检查常见密码、验证码、密钥、银行卡号及绕过确认的文本；自动经验还会参数化本次文字输入和追问回答，并拒绝明显的电话、邮箱、固定坐标。该检查不能识别所有未标注的私人信息，用户应在管理页检查和删除不合适的条目。

经验来源标为模型报告完成，不能替代实际任务验收。当前实现属于基于经验检索的上下文学习；没有修改模型权重、自动改写程序或省略当前屏幕观察。离线回归验证保存、相关性检索、下次请求注入、开关、反馈、个人偏好确认和损坏存储降级；真实模型的经验质量、跨任务收益与成功率提升仍需真机重复任务测量。此功能不代表 FR-MEM-03 问屏幕或 FR-MEM-05 快速模板执行已经完成。
