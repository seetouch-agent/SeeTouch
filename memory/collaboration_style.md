# 协作约定

更新时间：2026-10-12。保留长期偏好，不公开个人对话原文或本机目录信息。用户当前会话的明确指令优先。

## 实现与排查

- 模块化和合理分层，设备/模型实现遵循 Protocol；避免单文件堆叠。
- 先查当前代码、配置、日志和真实输出，再引用旧记忆。接口、默认模型和验证状态需要区分入口与版本。
- bug 先说明机制和证据，再修复；不要靠连续重试掩盖根因。
- 常规细节可自行决定并说明取舍；复杂架构先明确方案，小修不必增加流程。
- OPEN 不维护全量硬编码包名表；当前以本机显示名索引为准，旧小静态表偏好已被新方案替代。
- 不假定模型输出格式稳定；解析失败、API 错误和任务成功必须区分。
- thinking 开关由使用者决定，不能为了缩短耗时擅自关闭。

## 工作方式

- 普通检查、已有测试和已授权工作自行完成；物理弹窗和账号验证给出清楚的用户操作步骤。
- 步骤式指导在有意义的用户操作节点停下，等待实际结果再继续。
- 不自行删除文件，包括临时探针；说明位置和用途，由用户决定清理。
- 保留已有未提交修改，不把无关 Android Studio 配置混入提交。
- 不静默给全局 Python 安装重型依赖。
- 提交信息使用简洁中文，描述具体问题或行为。提交/推送遵循本次会话授权。
- 产品文案直接准确，避免使用 MVP 称呼。

## 公开身份与隐私

- 保留项目作者署名；Git 作者和提交者统一使用 GitHub `YidaYang` 的显示名 `Yida Yang` 及已核实的 noreply 地址，不添加 AI 联合署名。此约定适用于当前由维护者独立维护的项目。
- 公开文档和记忆使用相对路径/占位符，不写私人邮箱、key、设备序列号或个人目录。
- 审计只报告敏感信息的类别和位置，不回显原文。
- 历史改写、强推和本地 checkpoint 清理单独说明影响；`.gitignore` 不会移除已有历史对象。
- 记忆写入只在用户明确要求时执行；本次已授权同步项目 memory。
